# 구성과 데이터 흐름

Tauri 호스트가 OS 창·트레이·자동 실행·전원 알림과 로컬 파일을 소유한다. TypeScript 화면은 네이티브 명령으로 채널·설정·정보를 받고, 오디오는 WebView 안의 단일 재생기를 통해 공식 CDN에서 직접 받는다. 자체 백엔드나 공유 저장소는 없다.

채널 선택은 화면 → 재생 제어기 → 요청 ID가 있는 네이티브 주소 조회 → 방송사 어댑터 → 일시 스트림 URL → 오디오 재생 순서다. 주소 조회 완료와 오디오의 실제 playing 이벤트는 다른 경계다. 네이티브 취소 명령은 주소 조회를 중단하고, 프런트 취소는 오디오와 HLS 요청을 정리한다.

프로그램 조회는 별도 정보 경로다. 네이티브 계층이 방송사별 조회를 합치고 정규화한 시간 구간을 반환한다. 화면의 정보 갱신은 재생기의 수명을 소유하지 않는다. 설정 제어기는 사용자 변경을 직렬화하여 네이티브 파일 저장으로 보낸다.

OS 복귀 알림은 호스트 → system-resumed 이벤트 → 재생 제어기로 전달된다. OS 로그인 실행과 사용자의 직접 실행은 시작 인자로 구분한다. 트레이와 창이 같은 프로세스·설정 저장 주체를 공유한다.

외부 의존성은 방송사 조회 서비스, 공식 미디어 CDN, 설치 시 필요한 Microsoft WebView2다. GitHub Actions는 설치파일을 만드는 빌드 환경이며 앱 실행 중에는 필요하지 않다.

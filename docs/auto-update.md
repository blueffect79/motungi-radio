# 앱 내 업데이트

시작 15초 뒤와 실행 중 6시간마다 새 버전을 확인하고, 있으면 다운로드·서명 검증 후 메모리에 준비한다. 재생은 유지한다. 준비 알림 또는 설정의 ‘업데이트하고 재시작’을 사용자가 눌러야 설치한다. 실패하면 기존 앱을 계속 사용하며 설정에서 재시도한다. 종료 후 미설치 파일은 다시 내려받는다. 버전 내리기는 허용하지 않는다.

Mac·Windows·Linux AppImage 지원. Debian 설치는 홈페이지에서 새 패키지를 받는다. Windows 파일의 업데이트 서명은 Authenticode와 별개이며 SmartScreen 경고를 없애지 않는다. 기존 0.2.7에는 업데이터가 없으므로 최초 지원 버전은 한 번 수동 설치해야 한다.

## 배포 준비

공개키는 tauri.conf.json에 있고 개인키는 저장소 밖 `~/.config/motungi-radio/updater.key`에 보관한다. 이 키를 별도로 안전하게 백업해야 한다. 키를 잃으면 기존 사용자에게 자동 업데이트를 제공할 수 없다. 개인키·키 내용을 로그, Git, 공개 아티팩트에 넣지 않는다.

업데이트 번들 빌드에는 `TAURI_SIGNING_PRIVATE_KEY`를 키 파일 경로로 설정하고 `--config src-tauri/tauri.updater.conf.json`을 사용한다. 일반 빌드는 업데이트 번들을 생성하지 않는다. CI는 운영자가 동일 키를 GitHub Actions secret으로 등록한 뒤 해당 빌드 단계에만 전달해야 한다. 현재 CI에 개인키를 업로드하지 않았다.

Mac은 Developer ID 서명과 공증이 끝난 .app을 사용한다. DMG 공증만으로 updater tarball의 최종 내용을 검증했다고 판단하지 않는다. 앱 자체에 공증 확인표를 첨부하고 검증한 뒤 .app.tar.gz를 만들고 최종 tarball을 `tauri signer sign`으로 서명한다. 이후 파일을 변경하지 않는다. Windows NSIS와 Linux AppImage에도 동일 업데이트 키로 서명한다.

파일명은 `scripts/create-update-manifest.mjs`의 네 플랫폼 이름을 따른다. 각 파일과 `.sig`를 준비하고 스크립트로 latest.json을 생성한다. 이 스크립트는 누락·서명 형식만 검사하며 실제 암호학적 검증과 설치 시험을 대체하지 않는다.

1. 새 버전 설치파일·업데이트 파일의 OS 서명/공증·CPU·해시를 검증한다.
2. 이전 버전에서 정상 업그레이드, 잘못된 서명 거절, 네트워크 실패 시 기존 앱 유지, 설정 유지·무음 재시작을 실제 OS에서 시험한다.
3. 업데이트 파일과 `.sig`를 GitHub Release에 공개하고 익명 다운로드를 확인한다.
4. 마지막에 생성된 latest.json을 `site/updates/latest.json`에 추가해 Pages를 배포한다. 모든 플랫폼 준비 전 피드를 공개하지 않는다.

현재 로컬 구현 상태이며 공개 피드·지원 설치본 배포 및 실제 앱 교체 시험은 아직 진행하지 않았다. 존재하지 않는 피드는 확인 실패로 표시하고 청취를 유지한다.

자동 다운로드 ON/OFF 설정은 추후 구현한다. 현재 자동 확인·다운로드는 기본 동작이다. 설정 하단의 모퉁이 라디오 정보에서 빌드 버전과 소개·공식 링크·프로젝트 라이선스를 확인한다.

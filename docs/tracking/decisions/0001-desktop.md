# Mac과 Windows 공동 구현

Mac 전용으로 시작하면 사용할 수 있는 사람이 제한되므로 사용자 요청에 따라 Windows를 동시에 제공한다. 무료 직접 설치를 목표로 하며 별도 운영 서버 예산은 두지 않는다.

Tauri·TypeScript 화면과 Rust 네이티브 경계를 선택했다. Mac 전용 구현은 Windows 요구를 충족하지 못하고, OS별 독립 UI 두 벌은 채널과 프로그램 규칙 변경을 중복 관리해야 하므로 선택하지 않았다. 운영 서버를 두는 방식은 계정·가용성·비용 부담이 생겨 이번 제품 모델과 맞지 않는다.

화면·규칙을 공유하는 대신 WKWebView와 WebView2의 HLS 차이를 시험해야 한다. 네이티브 HLS와 번들 HLS.js를 함께 사용하며, 한 OS 빌드만으로 다른 OS의 청취 성공을 보장할 수 없다. 서버에서 스트림을 재송출하는 기능은 현재 구조에 포함되지 않는다.
